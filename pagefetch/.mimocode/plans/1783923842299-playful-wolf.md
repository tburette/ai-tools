# Plan: Make pagefetch globally available as a CLI tool
## Context
**User's request** (verbatim):
> "I want to have this tool installed globally, so I can use it from the command line even if mimo is not involved. I switch node version often with nvm so the ways it is installed must take it into account."

**pagefetch project** (`/home/tburette/dev/pagefetch`):
- `bin/pagefetch.js` — CLI entry point, uses commander, `#!/usr/bin/env node`
- `src/fetcher.js` — core logic: `fetchPage(url, options)` using playwright-extra + stealth plugin
- Dependencies: commander, playwright, playwright-extra, puppeteer-extra-plugin-stealth
- CLI args: `<url>` (required), `-o/--output`, `-w/--wait`, `-t/--timeout`, `-u/--user-agent`

**PATH** (user's current):
```
/home/tburette/.local/bin        ← target for symlink
/home/tburette/.nvm/versions/node/v24.16.0/bin  ← changes with nvm
...
```
---
## Step 1: Make bin/pagefetch.js executable
```bash
chmod +x /home/tburette/dev/pagefetch/bin/pagefetch.js
```
Currently not marked executable. Required for the symlink approach to work.
---
## Step 2: Create symlink in ~/.local/bin/
```bash
ln -s /home/tburette/dev/pagefetch/bin/pagefetch.js /home/tburette/.local/bin/pagefetch
```
**Why this works with nvm**: The script uses `#!/usr/bin/env node` which resolves to whatever `node` is in PATH at runtime. The symlink itself is just a file path in `~/.local/bin/` — not tied to any node version directory. When the user switches nvm versions, the same symlink picks up the new node automatically.
**After this step, the CLI works globally:**
```bash
pagefetch https://example.com
pagefetch https://example.com -w networkidle -t 60000
```

1. **CLI works**: `pagefetch https://example.com` outputs rendered HTML
